# Notes for Claude (and humans) working in this repo

The new, static version of quer-durch-asien.de. The plan and the reasoning
live in the legacy repo: `docs/new-setup.md` and `docs/migration-blog.md` in
[`sken/quer-durch-asien`](https://github.com/sken/quer-durch-asien).

## Deploy: Vercel, through its Git integration

There is no deploy workflow file; Vercel builds this repo (Turborepo,
`turbo.json`) as two projects:

| Vercel project | Folder | Production |
|---|---|---|
| `quer-durch-asien-next-web` | `apps/web` | `next.quer-durch-asien.de` |
| `quer-durch-asien-api` | `apps/api` | being retired: the site goes static |

- **A merge to `main` is a production deploy.** Treat `main` as production:
  no direct pushes or experiments there.
- **Every other branch gets a preview deployment** (behind Vercel login).
  That preview is the test environment: a PR is ready for review only when
  its preview builds succeed (visible as commit statuses on the PR).
- After a merge, check the production deployments and the affected pages on
  `next.quer-durch-asien.de`.

## Git workflow: PRs are squash-merged

- After a PR is merged, never push more commits to its branch. Start a new
  branch from the latest `origin/main` with a new name.
- One branch per PR.
- Never pipe a merge or rebase into another command and chain commits after
  it: a conflicted merge then looks successful. Check `git status` and grep
  for `<<<<<<<` before committing.
- Before pushing: `git fetch origin && git log --oneline origin/main..HEAD`
  should list only the commits of this change.

## Testing

Test what the change is about. "No JavaScript errors" misses blocked
requests (mixed content) and missing data; watch the console and the network
for the thing being changed, and say clearly when something could not be run.

## Generated content

`apps/web/data/` and `apps/web/content/` are generated by `tools/export` in
the legacy repo (see `apps/web/data/README.md`). Do not edit them by hand;
change the export and re-run it.

## Public repository

This repo is public. Never add personal data (users, comments, e-mail
addresses), database dumps, credentials or `.env` files.
